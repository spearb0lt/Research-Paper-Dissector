Dissect: architecture and workflow

A research paper is parsed into elements, and the element is the unit of everything after that. A paragraph, a table, a figure, a display equation and a reference entry are all rows in one table, which is what lets the reader overlay, All Views, retrieval and a citation all read the same rows, and what lets a citation point at a bounding box on a page rather than at text that has lost its origin.

1  Request lifecycle

Every request crosses the same four boundaries. In development the browser talks to the backend directly, because Next's dev rewrite buffers server sent events: the first token of an answer arrived at 0.0s direct and 19.0s through the proxy, which reads as a broken feature rather than a proxy. In production Vercel serves /api same origin, so the base is empty.

  • Provider key pasted in Settings lives in localStorage only
  • Everything the UI does is also a CLI command

  • Reads SSE for upload, answers and batch lens

Middleware chain

server/main.py

  • Keys bound to a contextvar for one request, then forgotten
  • Never written to disk, never logged
→

Routers, 41 routes

server/api/routes.py  ·  extras.py
  • Both mounted under /api
  • SSE: /papers/stream, /ask/stream, /lenses/batch
  • Typed handlers per error class, never a bare 500
Errors are answers. ParseError, LLMError, EmbeddingError and CapabilityError each have a handler that returns a message and a hint the UI renders. A feature the platform cannot provide reports itself unavailable with a reason, rather than failing at call time with an ImportError.

2  Ingest pipeline, the write path

server/pipeline.py drives six stages and emits progress at each one, so a long parse reads as working rather than hung. Any exception records why on the paper's status: a row left at parsing never resolves and holds its storage for ever.

1. Acquire

api/routes.py · server/fetch.py
  • Upload, or arXiv id, DOI or URL
  • SSRF guard: host resolved and re-checked on every redirect
  • PDF magic bytes verified
→

2. Store

server/blobs.py
  • SHA-256 content addressed
  • Dedupe by file_hash: the same PDF twice is parsed once
  • Disk, or the database where there is none

  • Falls back to fast if deep raises

  • Quality graded: good, fair, poor
  • Counts and page geometry stored
→

5. Index

  • Both written as BLOBs on the paper

6. Ready

status = ready

  • The UI shows elements while the index is still building

Fast tier, about 25 MB

parse/fast.py · tables.py · formulas.py · sections.py · citations.py
  • PyMuPDF for structure, text, figures and page rendering
  • pdfplumber for ruled tables
  • Tables: horizontal rule bands, then x-projection whitespace corridors. Constants were swept against five hand checked tables; a text based strategy once found seventeen tables in a paper that has four
  • Equations: detected by the absence of a body font on the line, not the presence of a math one
  • Captions linked both ways, conventional side first

Deep tier, about 2.5 GB

parse/deep.py · parse/ocr.py
  • Docling layout model and TableFormer
  • Figure extraction from the document model
  • RapidOCR on onnxruntime, no system binary
  • Needs roughly 2 GB of RAM, so it is unavailable on serverless and says so
Not a paid upgrade on Vercel. The models do not fit in a function bundle at all.

3  Storage

One schema, two dialects. Queries are written once with ? placeholders and rewritten for Postgres, so a literal % never appears in query text. Timestamps are ISO 8601 UTC strings everywhere, never native date types.

Engine

server/db/engine.py
  • SQLite by default, Postgres when DATABASE_URL is set
  • Type tokens: {PK} {JSON} {BLOB} {BOOL} {TS}
  • NUL stripped from every string: Postgres refuses it, SQLite stores it, and one PDF carried 174,576 of them
  • Bytes are never touched: 0x00 is ordinary BLOB content

Schema, 10 tables

server/db/schema.py
collectionspaperselements chunksthreadsmessages analysesnotesusage_log blobs
Migrations ALTER on every boot, each inside a savepoint. In Postgres one failed statement aborts the whole transaction, so a swallowed error once discarded all ten CREATE TABLEs.

Indexes live on the paper

papers.lexical_index / dense_index
  • Stored whole as BLOBs, because they are read whole on every search
  • dense_signature records which backend built the matrix
  • A search against a matrix from another backend is meaningless, so it rebuilds instead

Blobs, and where they go

server/blobs.py
  • Persistent disk present: filesystem
  • None present: the database, filesystem becomes a read cache
  • Content addressed, so shared: a blob is garbage only when nothing points at it
  • Deleting a paper sweeps orphans and reports the bytes freed
Attention costs 2.8 MB. ColPali costs 31 MB, for twenty figures and 26 pages.

4  Retrieval, the read path. This is the whole of no-LLM mode

Retrieval needs no API key and no model. It returns ranked chunks with pages, scores and a per leg breakdown, which answers where in this paper is X exactly. It is the default when nothing is configured, and the toggle stays visible when something is.

Chunk

index/chunk.py
  • 450 tokens, 80 overlap
  • Section path prepended to every chunk
  • Tables and figures chunk atomically
Deterministic context, not an LLM written sentence per chunk: that was measured as mostly recovering the position the parser already knows.
→

Leg A: lexical

index/lexical.py
  • Hand written BM25
  • Science aware tokeniser keeps 41.0, BLEU-4, p<0.05 whole
  • A word tokeniser shreds exactly the discriminating terms
→

Leg B: dense

index/dense.py · embeddings/
  • numpy cosine, brute force and exact
  • A paper is a few thousand vectors: no vector database
  • Doc ids carry an int/str tag through serialisation
→

Fuse

index/fuse.py
  • Reciprocal rank fusion, k = 60
  • Weights shift with the shape of the query
  • Diversified, then label pinned
→

Rank

index/rerank.py
  • Optional cross encoder
  • Needs PyTorch, so off on serverless
  • Filters by kind, section and paper

The bug the eval exists to catch

The dense index once serialised chunk ids as strings while BM25 kept integers, so fusion saw "37" and 37 as different documents and never merged a single result. Hybrid search silently ran as two independent single leg searches, which halves quality and is invisible in the output. The eval asserts at least one result is found by more than one leg.

Label pinning

ask/retrieve.py

"What does Figure 3 show" is a lookup, not a ranking problem. A named label is resolved exactly and pinned into the results with a score that survives the later re-sort, which is what makes questions about a specific figure or table work at all.

Find everywhere

ask/retrieve.py · /api/find

Exhaustive rather than ranked: one term, and every place it appears, whether that is a chunk, a table cell, a caption, a figure's OCR text or a reference entry. This is the All Views search.

5  Answering, the optional layer

A model is never required, and is never trusted with structure. Everything below sits on top of retrieval that already works without it.

  • Each carries paper, page and element
  • Comparison mode interleaves papers
→

Vision

answer.py → vision_payload
  • Figure crops attached as images
  • The prompt states an attached image is an excerpt
  • Gemini, Anthropic and OpenAI protocols
→

Provider

llm/registry.py · providers.py · streaming.py
  • 19 providers, 17 speak the OpenAI protocol
  • Key from the server env or the browser
  • Streamed as deltas over SSE
→

Validate

answer.py → validate_citations
  • Every [n] must resolve to an excerpt
  • Brackets normalised first: one provider emits 【1】
  • Unresolvable citations are stripped, not shown
→

Render

components/AnswerBody.tsx
  • Citation jumps to the evidence card
  • Evidence links to the page and its bbox
  • Nothing model written reaches dangerouslySetInnerHTML

Lenses

ask/lenses.py · analyses table

Named analyses over one paper, and comparison lenses over several. Results are cached per paper and lens, so a batch run over a library pays only for what is new: measured at 4 papers in 64 s, and 0 s on a re-run.

Keys, per request

llm/keyring.py

A key pasted in the browser is stored in localStorage, attached as a header on that visitor's own requests, bound to a contextvar for the life of one request, and forgotten. That is what lets a public deployment cost its operator nothing.

Metering

ops/meter.py · usage_log

Tokens and estimated cost recorded per call, per provider and per paper, so the usage screen reports what was actually spent rather than an estimate made in advance.

The reader overlay is the honesty feature. Boxes are positioned in percentages of the page's own point dimensions, so they stay aligned at any width. A table whose columns are wrong, a figure cropped badly or a heading that was missed all become obvious the moment the boxes are drawn, which is what makes a citation verifiable rather than merely plausible.

8  What keeps it honest

Type checks and builds caught none of the real bugs in this project. The eval encodes every one of them as an assertion, because each was invisible in normal output.

Parsing

ops/eval.py

Column counts against five hand checked tables, including a 13 column ablation grid. Formula counts, titles, abstracts.

Retrieval

ops/eval.py

Eight questions with the page the answer is really on. Asserts a result found by more than one leg.

Portability

ops/eval.py

NUL stripped from text, and kept in bytes. The second is the more expensive mistake.

Storage

ops/eval.py

A blob survives the local filesystem being deleted, and an unreferenced one is swept.

Operations

ops/cli.py

doctor, eval, add, search, ask, reindex, delete, gc.

9  Deliberately not in this diagram

A vector database

A paper is a few thousand vectors. A numpy matmul is exact, sub-millisecond and has no service to run. Chroma was removed: its HNSW backend serialises segment files per client, so two collections sharing a directory leave one with no segment files on disk.

An LLM summary per chunk

Measured as mostly recovering the chunk's position in the document, which the parser already knows exactly and prepends for free. The section path does the same job deterministically and costs nothing.

Page level visual retrieval

ColPali and similar: roughly a thousand vectors per page, about 8 GB of VRAM, and a retrieval unit of a whole page, which is coarser than the element level extraction this already has.
